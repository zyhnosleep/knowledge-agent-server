## 2. 固定应用骨架

- 参考画布为约 1680×945、16:9。
- 桌面侧栏宽约 270–278px，占画布约 16.5%；顶栏高约 70px。
- 侧栏与主内容、顶栏与内容之间只用 1px 冷灰线分隔，不使用大面积阴影。
- 品牌区由灯塔式线性标记、“夜航研究所 / NIGHT RESEARCH INSTITUTE”和 `RAG Research` 组成。
- 主导航固定为新聊天、文档库、运行；激活项是深灰横条、左侧白色竖线，图标为细线风格。
- 历史会话属于侧栏的长期区域；当前会话使用信号绿圆点，子会话以竖向时间线组织。
- 当前项目固定在侧栏底部，桌面端不随主内容滚动。
- 顶栏左侧是等宽英文视图编号与细线轨迹，右侧是绿色服务状态。

## 3. 视觉令牌

从原图提取并允许在相邻明度内微调：

```css
--night-950: #070a0e;   /* 页面与深层背景 */
--night-900: #0a0f14;   /* 侧栏 */
--night-850: #10161d;   /* 输入框、激活行、轻表面 */
--night-800: #151c24;   /* hover/active 表面 */
--night-700: #25303b;   /* 主要边界 */
--line-soft: #1b242d;   /* 表格与区块细线 */
--paper-100: #edf1f3;   /* 主文字 */
--paper-300: #b7c0c8;   /* 正文与次级文字 */
--paper-500: #7d8996;   /* 元数据 */
--signal: #a9ef58;      /* 唯一品牌状态绿 */
--evidence: #4d8dff;    /* 证据节点、引用与选中原文 */
--purple: #8b5cf6;     /* 仅保留运行类型进度差异 */
--amber: #f5a623;      /* 仅保留运行类型进度差异 */
--danger: #f06f73;
```

- 全局禁止蓝紫大渐变、玻璃拟态和厚重卡片阴影。
- 深度来自 1px 边界、色面微差、留白和局部节点辉光。
- 信号绿只用于已完成、在线、当前编号和关键焦点；不能成为大面积背景。
- 证据蓝只用于引用、知识节点、选中 chunk 与原文行动。

## 4. 排版系统

- 中文展示标题：`Georgia, "Songti SC", "STSong", "SimSun", serif`；重量 400–500。
- UI 正文：`Inter, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif`。
- 英文视图编号、指标、时间、索引：`ui-monospace, "SFMono-Regular", Consolas, monospace`。
- 桌面新聊天主标题约 54–60px、行高约 1.08；文档库/运行看板标题约 42–48px。
- 回答标题约 38–44px；正文约 14–16px、行高 1.8，阅读列宽约 720px。
- 英文顶栏标签约 11–12px、0.12–0.18em 字距。
- 不通过大量粗体建立层级；层级来自字体类别、尺寸、明度与间距。

## 5. 间距与形状

- 主内容桌面横向起点约为侧栏后 36–44px；顶栏后留 28–36px。
- 大区块垂直间距约 28–40px；表格行高约 52–58px。
- 普通圆角约 6–10px；输入框约 10–12px；禁止到处使用 20px 以上胶囊。
- 内容区保持开放式，不给每个信息块加背景卡片。
- 输入框是主要框体：1px 中性边界、非常轻的内层色差、约 112–124px 高。
- 桌面按钮多为 32–38px 高的紧凑描边控件。

## 6. 新聊天空状态（图 1）

- 主舞台采用三列关系：左侧编辑标题与 Research Index；中右是稀疏证据星图；最右是窄项目概览。
- 标题“从一个问题开始研究。”最多两行，左对齐，不居中。
- 副文案不超过两行，标题与副文案后使用一条约 400px 的水平细线。
- Research Index 为三行开放列表：绿色 `01/02/03`、白色 `ASK/TRACE/READ`、灰色中文说明。
- 星图只包含少量节点、细线和 4 个真实研究主题标签；不能实现为粒子球。
- 项目概览是无外框窄栏：文档总数、运行记录、失败任务、知识覆盖。
- 输入框横跨主舞台下方，附件、Agent/RAG 选择位于左下，发送位于右下；下方有两条示例问题。

## 7. 回答状态（图 2）

- 回答页保持侧栏和顶栏不变，主区域由阅读列、淡化星图和右侧项目概览组成。
- 顶部显示 `回答 / 01` 与绿色完成点。
- 已完成检索轨迹是一条可折叠的低高度横向区域，不是多张思考卡片。
- 用户问题以开放文本出现，不使用巨大气泡。
- Agent 回答按文章排版：展示标题、三段正文、行内蓝色编号 `[1] [2] [3]`。
- 来源文献置于文章尾部，用细线分隔、等宽小号文本编号。
- 回答时星图亮度和对比度下降，避免与正文竞争。
- 输入框宽度缩到阅读列附近，保证后续继续提问。

## 8. 文档库（图 3）

- 页面标题区开放，不使用带阴影的 intro 卡片。
- 内容为 240px 左操作栏 + 自适应文档索引表。
- 左栏依次为上传投放区、当前项目下拉、项目统计；区域间用细线和空白分隔。
- 上传区为虚线矩形，不使用大按钮填充。
- 文档列表不是卡片列表；每行含绿色序号、真实标题/摘要、文件名、上传时间、状态、证据数、进入对话和删除。
- 标题列占最大宽度，英文标题允许两行；摘要为单行/两行截断。
- 状态使用小型绿色描边标签；操作以细线图标和文字呈现。

## 9. 运行看板（图 4）

- 页面由约 80% 运行主区 + 20% 右侧项目概览组成。
- 顶部标题和说明后是三个无卡片指标，以竖线分列。
- 运行追踪是单一开放式表格，列为文献/主题、进度、处理状态、执行时间、操作。
- 进度条保持不同颜色以区分主题，但饱和度受控。
- 右栏包含当前项目、总数、成功率细条和最近事件时间线。
- 现有 topic 数据不得删除，可转化为右侧概览/事件/主题摘要，或保留为可折叠次级区域；不能破坏进入主题对话。

## 10. 原文回溯（图 5）

- 打开原文后，运行主区压缩到左半，右侧抽屉从主内容边缘展开，占约 45%。
- 抽屉不使用浮层阴影，与页面通过 1px 竖线衔接。
- 抽屉顶部包含来源、处理状态、处理时间和关闭按钮。
- 下部为 PDF 预览 + RAG Chunk 列表的两列结构。
- 当前 chunk 使用证据蓝边框与蓝色编号；其他 chunk 是低对比深色行。
- 原文 PDF 白色页面是画面中唯一大面积亮色，周围必须保持足够暗色边界。
- 关闭抽屉后必须恢复图 4 的完整运行看板布局。

## 11. 动效与交互

- 主视图切换：160–240ms 淡入与 6–10px 位移。
- 星图：低频节点呼吸与轻微连接高亮，仅 `transform`/`opacity`；检索中增强，阅读时淡化。
- 表格行：hover 只提升背景明度和边界，不抬升卡片。
- 原文抽屉：240–320ms 水平展开；关闭恢复布局。
- 按钮：边界/文字/背景在 120–180ms 内变化。
- `prefers-reduced-motion: reduce` 时停用星图、位移动画和自动平滑滚动。

## 12. 响应式推导

- 1200px 以下：右侧项目概览可缩窄或折到主内容下方。
- 900px 以下：侧栏缩为图标轨；历史会话通过抽屉访问。
- 768px 以下：文档库左操作栏置于列表上方；表格允许受控横向滚动或切换为无嵌套的行布局。
- 运行看板右栏置于主表下方；原文抽屉全宽覆盖主内容但保留关闭按钮。
- 480px 以下：使用先前批准的移动端逻辑，底部导航替代侧栏；输入区动作可换行，触控目标至少 44px。

## 13. 功能不可回归

- 保留所有现有 DOM id、API URL、project/document scope、会话/附件/删除/上传行为。
- 保留 Agent/RAG 模式、SSE 思考步骤、Enter/Shift+Enter/IME 语义。
- 保留文档级对话、主题级对话、源文件打开、PDF page hash、chunk 切换。
- 回答和来源内容只能通过安全 DOM 节点与 `textContent` 写入，禁止原始 HTML 注入。
- 页面无 hash 时默认进入新聊天；显式 `#files` 与 `#runs` 仍然工作。

## 14. 验收方式

- 运行静态前端测试、JavaScript 语法测试和全量 pytest。
- 在 1680×945、1440×900、1024×768、390×844 截图核对布局。
- 对五个状态逐一做浏览器视觉检查；允许内容数据不同，不允许布局语言、层级和视觉节奏漂移。
- 所有视口必须满足 `document.documentElement.scrollWidth <= window.innerWidth`，仅明确的表格滚动容器除外。
