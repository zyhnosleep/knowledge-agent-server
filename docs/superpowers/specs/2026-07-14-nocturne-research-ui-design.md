# 夜航研究所 UI 设计规格

**日期：** 2026-07-14  
**状态：** 用户已批准  
**实施范围：** 分阶段改造；本轮为阶段一（全局框架与对话主页）

## 1. 目标

把现有的通用深色 RAG 管理界面升级为具有明确品牌记忆的科研对话产品。阶段一必须让用户打开系统后立即进入一个高级、动态但适合长时间阅读的对话空间，同时保留现有项目、会话、附件、文档范围、RAG/Agent 模式和服务状态能力。

最终设计名称为“夜航研究所”。它不是霓虹控制台，也不是纯内容网站，而是编辑型研究排版与精密科研仪器的组合。

## 2. 已批准的设计决策

- 视觉比例：编辑型知识中枢 60%，精密科研仪器 40%。
- 动效：B 档“有节奏的动态”。交互、检索、引用建立与状态变化时运动；阅读时恢复安静。
- 默认入口：对话主场。没有显式 hash 时进入 `chat`，而不是 `runs`。
- 证据呈现：行内编号脚注。回答正文保留安全、可点击或可聚焦的引用标记，回答末尾提供与编号对应的来源列表。
- 默认主题：全局深色。使用墨黑、银灰、低饱和蓝与单一黄绿色状态色，不采用大面积蓝紫渐变。
- 空白会话主视觉：稀疏证据星图。节点与真实状态联动，避免持续旋转的“AI 粒子球”。
- 最终构图：A“夜航研究所”。编辑排版和留白是主角，星图是安静的背景层。
- 改造范围：先设计全套体系，分阶段实现。阶段一先改全局框架与对话主页；文档库和运行看板在后续阶段完整升级。

## 3. 阶段一信息架构

### 3.1 全局框架

- 左侧导航从 254px 的厚重侧栏收敛为更精密的窄侧栏，但必须继续显示产品名称、三项主导航、历史会话、新聊天入口、当前项目和用户信息。
- 顶栏只保留当前空间的语义标题、范围信息与服务状态，不与侧栏重复显示同一个大标题。
- 桌面端保持左侧导航 + 主内容；较窄屏幕下侧栏缩为图标轨，移动端改为顶部或底部紧凑导航，不能压缩对话正文到不可阅读。
- `files` 与 `runs` 在阶段一继续使用现有功能和主要 DOM id；全局颜色、字体、边框和控件基础样式可以同步适配，不能删除入口或改变 API 行为。

### 3.2 默认对话页

- 页面无会话内容时，中央展示编辑型标题“从一个问题开始研究。”、当前项目/文档范围、稀疏证据星图、轻量能力指标和固定在视口下方的输入区。
- 星图使用原生 HTML/CSS/SVG，不引入远程图像或运行时依赖；动画只改变 `transform` 与 `opacity`，并在 `prefers-reduced-motion: reduce` 下停止。
- 用户提交问题后，欢迎区退出，星图淡出；对话进入纵向阅读流。
- 用户消息保持右对齐但弱化聊天气泡感；Agent 回答使用更宽的编辑型文章版式。
- 思考步骤呈现为紧凑的纵向状态轨迹，新增步骤有短暂进入动画，完成后不持续闪烁。
- 输入区减少当前 150px 的占用，保持附件、模式选择、发送、Enter/Shift+Enter 语义和自动增高。

## 4. 视觉系统

### 4.1 色彩

建议设计令牌：

- `--night-950: #070a0e`：应用背景。
- `--night-900: #0b1015`：侧栏与深层容器。
- `--night-850: #10161d`：交互表面。
- `--night-700: #25303b`：高可见边界。
- `--paper-100: #edf1f3`：主要文字。
- `--paper-300: #b7c0c8`：次级文字。
- `--paper-500: #7d8996`：辅助说明。
- `--signal: #b1ef63`：就绪、成功、当前节点等单一品牌状态色。
- `--evidence: #8faaff`：引用、证据节点和可追溯链接。
- `--danger: #f06f73`：删除与错误。

状态色必须满足可读性；黄绿色不用于长段正文。

### 4.2 排版

- UI 控件继续使用本地系统无衬线字体栈，避免远程字体依赖。
- 空白页标题、回答标题或强调句使用系统可用衬线字体栈 `Georgia, "Songti SC", "STSong", serif`，建立编辑感。
- 状态、编号、指标和引用使用系统等宽字体栈。
- 正文宽度控制在约 68–76 个中文字符可读范围内，行高 1.75 左右。

### 4.3 形状与层次

- 主要容器圆角控制在 8–14px，不使用大量 20px 以上胶囊卡片。
- 依靠细边框、留白、色温和局部高光建立层次；避免现有的厚重“下沉硬阴影”。
- 按钮有清晰的默认、悬浮、焦点、按下和禁用状态。
- 所有可点击元素必须保留可见的 `:focus-visible`。

## 5. 行内脚注行为

- 不再对 Agent 答案无条件执行 `stripCitationMarkers()` 后丢弃正文编号。
- 新增安全 DOM 渲染路径：只使用 `textContent`/文本节点解析正文中的 `[1]`、`[1, 2]` 等标记，生成 `sup` 引用，不使用原始 `innerHTML` 注入回答内容。
- 引用编号与去重后的 citation 顺序保持一致；存在 URL 时编号链接到文档文件端点并新窗口打开，不存在 URL 时仍显示可聚焦编号。
- 回答末尾的来源列表按同一编号展示真实标题；附件来源无文档 URL 时保留纯文本。
- 历史 Agent/tool 消息使用同一安全引用渲染逻辑。
- 无 citation 数据或正文编号越界时，原文本必须可读，不能产生空链接或异常。

## 6. 动效与无障碍

- 页面进入、欢迎区退出、思考步骤增加、答案出现和服务状态变化使用 160–420ms 的缓动过渡。
- 星图节点可以进行低频呼吸或短距离漂移；检索期间才增强亮度或建立连线。
- 禁止持续大幅位移、背景自动滚动、闪烁频率高于可访问性安全阈值的效果。
- `prefers-reduced-motion: reduce` 时关闭星图、轨迹进入和装饰动画，并把滚动行为改为即时。
- 语义标题层级、表单标签、按钮 `aria-label`、服务状态和键盘操作必须继续可用。

## 7. 功能保护线

阶段一不得破坏或移除：

- 项目切换与项目范围标签。
- 单篇文档范围对话。
- 历史会话加载、选择和删除。
- 新聊天清空状态。
- 临时附件上传、显示和删除。
- Agent/RAG 模式切换。
- SSE Agent 步骤、回答与引用。
- Enter 发送、Shift+Enter 换行和 IME 安全。
- 文档库、运行看板、原文回溯及其现有 API。
- 服务健康状态。

## 8. 响应式要求

- 1440px：完整侧栏、宽阅读列、星图与标题形成不对称平衡。
- 1024px：减少外围留白，保留完整导航和正文宽度。
- 768px 以下：侧栏缩为紧凑导航，不保留占宽的会话列表；输入区动作可换行。
- 480px：标题缩放、星图降低存在感、正文与输入控件不横向溢出。

## 9. 阶段一验收

- 无 hash 打开首页时默认显示 chat；显式 `#files` 与 `#runs` 仍正常。
- 欢迎页包含可识别的“夜航研究所”排版、证据星图和当前范围。
- 对话、会话、附件、文档范围和模式切换的既有静态测试继续通过。
- 新增静态测试覆盖默认路由、设计令牌、星图结构、减弱动效、行内引用安全 DOM 渲染和响应式断点。
- 内联 JavaScript 通过 `node --check`。
- `python -m pytest tests/test_static_frontend.py -q` 通过。
- 浏览器在 1440×1000、1024×768、390×844 三种视口下无横向溢出，关键入口可见。
- 首页健康检查和对话发送至少完成一次手工烟雾测试。

## 10. 后续阶段

- 阶段二：文档库升级为编辑型研究档案，强化上传、索引状态和文档级对话入口。
- 阶段三：运行看板升级为精密科研仪器视图，保留主题、运行、原文和 chunk 回溯能力。
- 阶段四：统一空状态、错误状态、加载骨架、响应式细节和视觉回归基线。
