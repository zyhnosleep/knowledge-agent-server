# 02 — 文件入库场景（传文件 → 入正式库 → 回执）

**What to build:** 群里 @ 机器人并发送文件（PDF/docx/txt/md/html 等系统支持类型）时：下载文件 → 写入 `feishu-inbox` 项目（项目不存在则自动创建）→ 等待入库完成（解析+分块+嵌入）→ 回执"已入库 N 篇"及文件名；任一环节失败（下载失败/类型不支持/大小超限/解析失败）→ 回执明确原因，不静默吞错。入库期间先回"正在入库"占位回执。

**Blocked by:** 01 — 平台配置清单 + 长连接事件通路（骨架）

**Status:** ready-for-agent

- [x] `feishu-inbox` 项目不存在时自动创建（upload 接口 register_document 按 slug 幂等）
- [x] 群里发 PDF 并 @ 机器人 → 先收"正在入库…" → 入库完成后收"已入库 1 篇（报告.pdf）"
- [x] 入库完成的判定 = 文档状态 ready（轮询 /documents/{id} 至终态），不是文件落盘
- [x] 加密/损坏 PDF → 回执"入库失败（parse_failed）"
- [x] 类型不支持 / 大小超限 → 回执上传失败原因（API detail 透传）
- [x] 下载失败（飞书文件过期等）→ 回执"下载失败：<原因>"
- [x] 多文件同传 → 逐条文件消息处理（飞书单条消息只含一个文件），回执逐条给出结果
