# 04 — 混合场景（一条消息带文件 + 提问）

**What to build:** 群里 @ 机器人且一条消息同时携带文件与文字问题时：回执"正在入库并回答" → **先完成入库**（文件进入 `feishu-inbox` 正式库并 ready）→ 再基于入库后的语料回答问题 → 推送最终回复（含入库确认 + 答案，答案能引用刚入库的文档）。复用 02 的入库链路与 03 的问答链路，本票只做编排与状态衔接。

**Blocked by:** 02 — 文件入库场景 + 03 — 文本提问场景

**Status:** ready-for-agent

> 实现注记（2026-08-20）：飞书单条消息要么是 text 要么是 file，不存在
> "一条消息带文件+文字"。混合场景按用户 Q8 澄清的真实语义实现：文件消息
> 与文本消息先后到达（相邻两条事件），per-chat 锁保证"先入库完成后回答"，
> 答案可命中刚入库的文档。单条合并回执验收调整为两条独立回执。

- [x] 一条消息带文件+文字 → 先收"正在入库并回答" → 最终回复同时含入库确认与答案（两条消息：文件回执"正在入库…/已入库" + 问答回执"处理中…/答案"，锁保证先入库后回答）
- [x] 答案检索命中刚入库的文档（per-chat 锁：问答等待同群入库完成）
- [x] 入库失败（如解析失败）→ 文件回执含明确失败原因（后续独立提问仍可回答，检索不到失败文档）
- [x] 问答失败 → 已入库确认已单独回执 + 问答失败原因回执
- [x] 多文件+提问 → 同群锁串行，全部入库完成后统一回答
